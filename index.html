Overview

What it does

The native Application Manager updates one application at a time. Now Plugin Updater groups updates into a single, monitored workflow, suitable for large or unattended runs.

Batch install

Filter, select multiple applications, and launch the batch in one action, instead of opening each application individually.

Server-side monitoring

Close the page once launch finishes. A scheduled job tracks every install, verifies the version, and marks each Complete or Failed.

No stored credentials

Installs are triggered with your own admin session. No passwords or tokens are stored.

Built on the platform

A single UI Page using vanilla JavaScript — no React, no bundler, no external libraries.

Release 1.6.2

What’s new

A packaging fix so the update set installs cleanly on any target instance, plus dependency impact you can trust before you click Install, a confirm dialog that names what you picked, and a Monitor that shows exactly which dependency apps were installed alongside your selection.

See what else will update

Selecting an app now shows every other application it will pull in — suite members and version-required dependencies — right in the wizard, with a per-row N more breakdown instead of one unclear shared list.

Confirm dialog names your selection

Before you launch, the dialog lists the applications you actually picked, separately from the dependencies they bring with them — no more guessing from a bare count.

Dependency installs, tracked per row

The Monitor shows each dependency app the platform actually installed nested under the row that triggered it, with its own status and progress — an observed fact, not a prediction.

Home always reflects the latest batch

Returning to Home from the Monitor now refreshes the dashboard automatically, so the app counters never show a stale pre-batch state.

No more silent truncation

Long selection and dependency lists in the confirm dialog now show a clear “Showing 150 of N” note instead of silently cutting off past the cap.

Verified outcomes

An install counts as Complete only if the application actually reaches the target version — never based on the platform’s own reported status alone.

Get started

Get started in three steps

Download the update set, import it into your instance, and open the app. You need the admin role.

Download the application

Download the update set — a single portable XML file containing the full app (UI Page, server logic, table, ACLs, scheduled job).

~274 KB · Update set v1.6.2 · Global scope — full install (table, fields, ACLs, module, scheduled job, Script Include, UI Page).

Install it on your instance

Import and commit the update set:

  1. In your instance, open All → System Update Sets → Retrieved Update Sets.
  2. Click Import Update Set from XML, choose the downloaded Now Plugin Updater.xml, and upload.
  3. Open the retrieved record and click Preview Update Set; resolve any preview problems.
  4. Click Commit Update Set.

Open and use it

The commit creates a Plugin Updater application menu and module.

  1. In the navigator, open All → Now Plugin Updater → Plugin Updater (or go to /now/nav/ui/classic/params/target/pgi_plugin_updater.do).
  2. On Home, review your instance and the Apps indicators, then click Start Wizard.
  3. Discover the apps with updates, Select the ones you want — expand any N more ▾ row to see suite members or dependencies that will update alongside it — and click Install.
  4. Review the confirm dialog, which lists both what you selected and what else it brings in, then confirm to launch.
  5. Switch to Monitor to watch progress — you can safely close the page; the server finishes and tracks each install, including any dependency installs it triggered.

Before you install

Requires the admin role and is built for Global scope. Because the app list mirrors the Application Manager, a few platform-bundled apps that can’t be updated via the Store API may end as Failed — this is expected. No credentials are ever stored. Dependency-impact detection has been verified on the Australia release family; it has not yet been verified on Zurich.
