Overview

What it does

The native Application Manager updates one application at a time. Now Plugin Updater groups updates into a single, monitored workflow, suitable for large or unattended runs.

Batch install

Filter, select multiple applications, and launch the batch in one action, instead of opening each application individually.

Server-side monitoring

Close the page once launch finishes. A scheduled job tracks every install, verifies the version, and marks each Complete or Failed.

No stored credentials

Installs are triggered with your own admin session. No passwords or tokens are stored.

Built on the platform

A single UI Page using vanilla JavaScript — no React, no bundler, no external libraries.

Release 1.7.1

What’s new

A bug-fix release: no new features, but the Wizard, the Monitor and the Store sync behave correctly in the cases a full code review and live tests found.

A select-all you can trust

The header checkbox is now tri-state (all, none, some) and clears the whole selection. The confirmation lists page through 25 applications at a time, so no application is hidden behind a cap.

One launch at a time

While a launch runs, the Wizard is blocked and applications already installing are not selectable again. Cancel queued now stops the browser, and says how many installs the platform had already queued.

Honest about failures

An expired session stops the launch with a clear message instead of marking apps failed. A row that is already Complete is never overwritten, and the installed version still has the last word.

A Monitor that recovers

One failed poll no longer freezes the Monitor or the Store sync: every server call has a watchdog and the page retries by itself. A sync started from the Application Manager is followed too.

Safer maintenance tools

The queue release re-checks that the install is still dead right before changing anything, and refuses if anything moved. The reset script ignores empty lists.

Store sync, kept private

The sync runtime state is no longer captured in your current update set, and the one-shot sync job starts reliably. Dependency impact keeps the highest required version.

Get started

Get started in three steps

Download the update set, import it into your instance, and open the app. You need the admin role.

Download the application

Download the update set — a single portable XML file containing the full app (UI Page, server logic, table, ACLs, scheduled job).

~475 KB · Update set v1.7.1 · Global scope — full install, 59 objects (table, fields, ACLs, module, scheduled job, Script Include, UI Page).

Install it on your instance

Import and commit the update set:

  1. In your instance, open All → System Update Sets → Retrieved Update Sets.
  2. Click Import Update Set from XML, choose the downloaded Now Plugin Updater.xml, and upload.
  3. Open the retrieved record and click Preview Update Set; resolve any preview problems.
  4. Click Commit Update Set.

Open and use it

The commit creates a Plugin Updater application menu and module.

  1. In the navigator, open All → Now Plugin Updater → Plugin Updater (or go to /now/nav/ui/classic/params/target/pgi_plugin_updater.do).
  2. On Home, review your instance and the Apps indicators, then click Start Wizard.
  3. Discover the apps with updates, Select the ones you want — expand any N more ▾ row to see suite members or dependencies that will update alongside it — and click Install.
  4. Review the confirm dialog, which lists both what you selected and what else it brings in, then confirm to launch.
  5. Switch to Monitor to watch progress — you can safely close the page; the server finishes and tracks each install, including any dependency installs it triggered.

Before you install

Requires the admin role and is built for Global scope. Because the app list mirrors the Application Manager, a few platform-bundled apps that can’t be updated via the Store API may end as Failed — this is expected. No credentials are ever stored. Dependency-impact detection has been verified on the Australia release family.
