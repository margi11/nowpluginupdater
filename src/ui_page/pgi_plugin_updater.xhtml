How to Use Now Plugin Updater

Overview

Now Plugin Updater lets a ServiceNow administrator discover, select, and install the available updates for Store applications on this instance from a single screen, replacing the per-app flow in the native Application Manager. You need the admin role to use it.

1 · Home

Shows the instance name and release, its data center and database, the signed-in admin, and the last upgrade date, plus four app indicators that reconcile: Apps (total managed = up‑to‑date + updates available), Up to Date, Updates Available, and Installing (running right now). Use Start Wizard to begin, Refresh Data to reload, or Monitor installs to open the monitor. Clicking the Installing card opens the batch currently running.

2 · Wizard — Discover

Lists every Store application with an available update (the same set the native Application Manager shows: active, visible, previously installed). Each row shows the scope and the current → latest version. Click any column header to sort ascending/descending.

3 · Wizard — Select

Filter by name, narrow by scope, tick the applications to update (or use Select All), then click Install and confirm. The buttons sit above the list, so you never have to scroll hundreds of rows to continue. Apps already being installed are shown as installing and cannot be re-selected.

Very long lists render the first 150 rows for speed — use show all or the filters to reach the rest. Select All always applies to everything matching the current filter, not just the visible rows.

4 · Launch & Monitor

  • Installs are triggered with your own admin session — no credentials are stored.
  • They are enqueued one at a time (the platform's CICD install API is single-flight); a busy queue is retried automatically, and a 400 “offering required” error is retried with the offering id.
  • Once launching finishes you can close the page: a scheduled job on the server tracks every install, verifies the installed version, and marks each Complete or Failed.
  • An install counts as Complete only if the application actually reaches the target version. If the platform reports success but the version did not change, the row is marked Failed with the version it stayed on.
  • Whenever a row carries a message, a Details (or Why failed) button appears in the last column. It opens the exact text reported by the platform underneath that row — useful for telling apart an app that was rejected at launch from one whose install did not apply. If any application fails to launch, the wizard stays on the Launch step so you can read the reasons before moving on.
  • The Monitor tab shows the batch with five counters — Total, Installing (running right now), Queued (waiting in the server queue), Complete, Failed — and a sortable per-app table. When the batch ends a summary appears, with a shortcut to list only the failures.
  • Cancel queued drops the applications still waiting in the queue. Installs already running cannot be interrupted and will finish.
  • Reopening the page reloads your most recent batch automatically; the batch selector lets you review earlier ones.

Notes

  • Because the list mirrors the Application Manager, a few platform-bundled apps that cannot be updated via the Store API will end as Failed — this is expected.
  • Keep the page open only for the few seconds of launching; installs and monitoring then continue on the server.
  • Sync with Store runs the same catalog check as the Application Manager and shows its real progress, then reloads the page when it finishes — typically a couple of minutes. If it is still running after five minutes the page stops following it and says so: the sync keeps going on the server and does not need this page open.

Access Control

This page, its data, and the install log are restricted to the admin role.
