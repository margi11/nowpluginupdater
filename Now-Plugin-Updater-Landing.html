Overview

What it does

The native Application Manager updates one application at a time. Now Plugin Updater groups updates into a single, monitored workflow, suitable for large or unattended runs.

Batch install

Filter, select multiple applications, and launch the batch in one action, instead of opening each application individually.

Server-side monitoring

Close the page once launch finishes. A scheduled job tracks every install, verifies the version, and marks each Complete or Failed.

No stored credentials

Installs are triggered with your own admin session. No passwords or tokens are stored.

Built on the platform

A single UI Page using vanilla JavaScript — no React, no bundler, no external libraries.

Release 1.4.0

What’s new

A correctness release: outcomes you can trust, a Store sync you can watch, and a wizard that no longer makes you scroll hundreds of rows to press a button.

Verified outcomes

An install counts as Complete only if the application actually reaches the target version. If the platform reports success but the version never moved, the row is marked Failed with the version it stayed on.

Store sync with real progress

The sync now reports the platform’s own phase-by-phase progress instead of an open-ended wait, and refreshes the page the moment it finishes.

Built for long lists

The action bar stays pinned to the bottom of the screen, so Next and Install are always one click away. Ticking a checkbox no longer redraws the whole table.

Confirm before you launch

A summary dialog names the instance and how many applications are about to be updated — installs are queued one at a time and cannot be undone.

Cancel what hasn’t started

Cancel queued drops the applications still waiting in the queue. Installs already running finish normally.

Clearer monitoring

An end-of-batch summary with a shortcut to list only the failures, a batch selector showing counts and outcome, plus status icons, keyboard sorting, and screen-reader announcements.

Screens

The three screens

A wizard to choose what to update, and a monitor that continues server-side after the page is closed.

Home

Instance overview

The header shows the instance name, release, data center, database engine, the signed-in admin, and the last upgrade date.

Four reconciling indicators — Apps, Up to Date, Updates Available, and Installing — summarise the current state.

Get started

Get started in three steps

Download the update set, import it into your instance, and open the app. You need the admin role.

Download the application

Download the update set — a single portable XML file containing the full app (UI Page, server logic, table, ACLs, scheduled job).

~216 KB · Update set v1.4.0 · Global scope

Install it on your instance

Import and commit the update set:

  1. In your instance, open All → System Update Sets → Retrieved Update Sets.
  2. Click Import Update Set from XML, choose the downloaded Now Plugin Updater.xml, and upload.
  3. Open the retrieved record and click Preview Update Set; resolve any preview problems.
  4. Click Commit Update Set.

Open and use it

The commit creates a Plugin Updater application menu and module.

  1. In the navigator, open All → Now Plugin Updater → Plugin Updater (or go to /now/nav/ui/classic/params/target/pgi_plugin_updater.do).
  2. On Home, review your instance and the Apps indicators, then click Start Wizard.
  3. Discover the apps with updates, Select the ones you want, and click Install.
  4. Switch to Monitor to watch progress — you can safely close the page; the server finishes and tracks each install.

Before you install

Requires the admin role and is built for Global scope. Because the app list mirrors the Application Manager, a few platform-bundled apps that can’t be updated via the Store API may end as Failed — this is expected. No credentials are ever stored.
